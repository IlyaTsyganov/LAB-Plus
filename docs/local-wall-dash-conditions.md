# Раннее прерывание dash: исследованная версия 1.1

> Отложено по просьбе пользователя 5 ноября 2026 года. В рабочей программе этой функции больше нет; см. deferred-wall-dash.md. Ниже сохранена история исследования.

Ниже разобрана конкретная ветка столкновения в DOOM Eternal 1.1, а не универсальное правило для всех патчей. Проверки установлены чтением кода EXE, действующих регистраций FSM и записей пользовательских демонстраций. Поведение игры не менялось.

## Что проверяет ветка удара о стену

| Условие | Подтверждение | Что это значит для подсветки |
| --- | --- | --- |
| Активен именно dash, состояние Active (2) | RVA 0x135A54F–0x135A553; живая таблица состояний | Просто находиться у подходящей стены недостаточно |
| Есть допустимый результат специального collision query | 0x135AC38–0x135ACE4; маска 0x108409 при подаче query | Нужна поверхность, реально встретившаяся этому запросу первой; задняя поверхность может быть недоступна |
| Не сработала приоритетная обработка взаимодействий | 0x135A962–0x135AC1B, итоговая проверка 0x135ACEC | Ветки melee target / destructible и teleporter могут пропустить обычную обработку стены |
| Вертикальная составляющая полученной нормали ровно 0 | 0x135ACF2–0x135AD00, unordered также отвергается | Почти вертикальная грань не эквивалентна вертикальному контакту; нормаль зависит от реальной точки/ребра столкновения |
| Модуль скалярного произведения нормали и нормализованной текущей скорости не меньше 0.7071067094802856 | 0x135A577–0x135A63A, 0x135AD06–0x135AD3E | Для обычного горизонтального движения это примерно 45° от поверхности стены. Используется текущая скорость физики, включая её базовую добавку, а не только изначальный dashDir |
| Другой переход ещё не активен и переход 2 допустим | 0x135AD44–0x135AD89; activeTransitionId по отражённой схеме +0x14 | Подходящий контакт не должен перебить уже принятый переход состояния |

После принятия перехода 2 автомат переходит из Active (2) в Idle (1). Это подтверждается действующей transitionsList: составная запись 0x02020001. Досрочное завершение до обычного спада скорости объясняет сохранение части скорости, но само по себе любое раннее завершение ещё не доказывает полезный wall dash.

Состояние 3 имеет нативное имя Enter_HitAI и отдельную обработку; в ней есть установка линейной скорости в ноль. Его нельзя приравнивать к успешному завершению удара о стену. Airborne не проверяется отдельным флагом в приведённой ветке, хотя для практического сохранения скорости и дальнейшего полёта состояние движения существенно.

## Взаимодействия

При dash_usesTouchingBoundsForCollide=1 движок собирает до восьми касающихся сущностей. При 0 используется исходная сущность контакта. В исследованном процессе значение равно 1. Нативные сообщения веток явно называют idTargetMelee и idDestructible и говорят о продолжении dash; эти ветки устанавливают флаг, который обходит обычную проверку стены. Ветка телепортера устанавливает тот же итоговый флаг при включённой проверке touching bounds. Класс телепортера подтверждён диапазоном типов idTrigger_Teleporter, включая Fade.

Сообщение, упоминающее AI/usable prop, само по себе не доказывает, что все AI или все props являются одинаковыми запретными объёмами. Внутренняя логика взаимодействия и состояние объектов должны рассматриваться отдельно. В оверлее не введено произвольного исключения всех trigger/volume или всех объектов по части имени.

Расширение bounds в этой функции также читает debug_dashDamageView; в исследованном сеансе это 0. Не следует подменять его догадкой о постоянной дистанции расширения.

## Результат query и точность наблюдения

Используются два чередующихся clipQuery; код предпочитает первый допустимый слот, затем второй, а не просто выбирает максимальный ID. При g_havokUseDeferredTracesLookupTable=1 потребляется готовый trace из отдельной таблицы. Промежуточный collector может относиться к предыдущему содержимому кольца.

Новый внешний наблюдатель читает границу опубликованных результатов +0x38, проверяет ID/range до и после чтения, записывает состояния FSM и добавочную скорость. Даже такие снимки не являются перехватом конкретного вызова функции. Полное совпадение каждого прочитанного trace с точным потреблённым вызовом не объявляется доказанным.

## Исправленные причины ошибок отображения

1. Проверка всей convex-формы отбрасывала пригодные грани из-за неточности плоскостей других граней. Теперь для подсветки грани проверяются независимо. Строгая проверка замкнутого тела для projectile trimming не ослаблена.
2. Подсвеченная плоскость могла находиться внутри другой физической коллизии. Теперь её закрытая часть получает обычный цвет World collision. Полная поверхность остаётся видимой; меняется только цвет кандидата.
3. Большая пригодная грань могла потерять подсветку целиком из-за лимита фрагментов при обработке многочисленных перекрытий. В v5 сложный треугольник делится на меньшие части в фоновом потоке. При достижении предела глубины обычный цвет остаётся только у сложной части. Другие ограничения подготовки сохраняются, поэтому полнота покрытия по-прежнему не гарантируется.
4. Неплоский нативный полигон может иметь внутреннее выпуклое ребро с возможным горизонтальным направлением контакта, хотя нормаль всего полигона наклонена. В v6 такие поддержанные геометрией рёбра отмечаются линиями цвета Wall dash; заливка прилегающей грани остаётся обычной. Для линий нужны включённые Outlines. Это геометрические кандидаты, без воспроизведения численного решателя Havok и без гарантии успеха при любом попадании.

Новые демонстрации записаны локально: 32 554 читаемых снимка, 0 ошибок чтения. Проверки на считанной геометрии подтверждают исправление показанных участков и сохранение ранее хорошей стены. Автоматические тесты проверяют отдельные грани, восстановление convex support hull, открытые поверхности, сохранение площади/прозрачности/контуров и старого вывода при выключенной опции.

## Остающиеся ограничения

Оверлей показывает потенциальные поверхности. Он не симулирует каждый будущий запрос с конкретной траекторией, текущей скоростью, порядком до восьми сущностей и состоянием автомата. Сложная или неподдержанная геометрия и пределы подготовки могут оставаться неокрашенными. Нормаль на скруглении/ребре может отличаться от нормали грани. Поздний успешный контакт может сохранить мало скорости. Эта логика не включена для других патчей без отдельного аудита.

Визуальная проверка новой версии модуля в игре остаётся отдельным этапом; анализ записей, сборка и синтетические тесты её не заменяют.
