## Executable evidence in 1.1

The runtime dash instance's class getter identified idAbility_Dash; its vtable RVA was 0x2904880. Relevant dash code includes:

- RVA 0x135C540 submits the alternating clip query with mask 0x108409 (the submission immediately before it uses the same mask).
- RVA 0x135AC38 and 0x135AC74 select the ability's existing clipQuery handles, validating their submitted status through 0xA2DD80 and obtaining a trace through 0xA2B590.
- RVA 0x135ACF2 reads the resulting trace contact normal Z and compares it to zero with ucomiss. Unordered and nonzero values bypass the wall-interrupt branch. This is exact float equality, not an approximate slope tolerance.
- RVA 0x135AD06 onward computes the normal/normalized-current-physics-velocity dot product. RVA 0x135AD37 compares its absolute value to the stored float 0.7071067094802856. Smaller magnitudes bypass the wall-interrupt branch. For normalized vectors this corresponds to approximately 45 degrees from the plane.
- The accepted branch requests transition 2 (Active state 2 to Idle state 1) and logs the native format `DASH stopped at %0.2f / %0.2f due to wall collision: %f`.

These are conditions within the inspected wall-collision interrupt path, not a complete proof of all dash state transitions. The additional state guard preceding the normal check and other interruption paths must be respected. No synthetic execution test or all-version compatibility result is claimed.

## Consequences for a future overlay

There is a real engine predicate supporting a separate surface highlight. It is not a blanket contents flag for "wall-dash wall", nor a test for visually flat or approximately vertical triangles. A highlight should identify eligible individual faces using the engine's actual collision geometry/normals and mask, keeping unsupported/unknown sources unclassified. Calculated render-triangle normals must not silently replace actual contact normals near beveled edges, rounded shapes or compressed/rotated geometry. A world face's eligibility also cannot guarantee speed retention at every impact angle, height or dash phase.

The predicate and live comparison are verified only for this 1.1 installation and the demonstrated locations. Other supported game builds require code verification before enabling the classifier for them. Existing World collision colors/rendering and the current local test build are unchanged. No PR, push or release was made.

The public [community tech guide](https://www.mdsr.run/de/view-docs.php?type=tech) was consulted for context; it describes wall dash but does not establish the exact normal-Z predicate. The conclusion above comes from local executable inspection and the user's read-only demonstrations.

## Optional local rendering implementation

It retains World collision's fill opacity and contour alpha, draw style, visibility, view distance, culling, inspector priority and vertex counts. Disabling World collision or the Viewer disables the child controls without discarding their settings. Color and enabled state persist and reach viewer.ini independently of ordinary World/Projectile/Trigger/Wall appearance settings.

The background scene builder classifies only known player-blocking native convex leaves with a certified plane/face/corner layout. Those contents also intersect the audited 0x108409 dash query mask. Native face order is mapped directly to the existing triangle fan and deduplicated polygon edges. An edge receives the highlight if either adjacent face qualifies; no new edge/triangle is emitted. Classification is cached with immutable geometry, independently of the transformed-position cache and presentation-time colors.

Eligibility requires native plane normal Z exactly zero. There is no epsilon or inference from visually vertical render triangles. Compound transforms must preserve the vertical axis exactly; tilted, singular, nonfinite and otherwise unsupported transforms remain ordinary. This restriction avoids making float rounding in an arbitrary inverse-transpose transform into a false positive. Compressed surfaces, missing contents/plane metadata, mismatched layouts, live dynamic volumes and non-world categories remain unclassified. Only the verified retail 1.1 profile enables classification; other supported versions keep their existing rendering even when this setting is saved on. The tooltip explains the experiment, 1.1 scope, unclassified surfaces and dependence on approach angle/timing.

The report exposed a problem in the implementation: collectVertices invoked WallDashRegionCache::get on the presentation thread, separately for fill and contours. That function could build convex support hulls, search blockers and partition polygons, spend its time budget, and return a temporary ordinary-color fallback. Time-limited meshes could restart expensive work on later frames; eviction or refreshed region bounds could repeat preparation. Fill and contours could observe different preparation states during one frame. A high FPS counter does not rule out individual long frame times.

Preparation now runs in a dedicated WallDashAsync worker over immutable world snapshots. The presentation path submits a canonical set of visible indices, reads one immutable completed snapshot and uses that same snapshot for fill and contours. It does not call the geometry builder. Equivalent target/region orders do not trigger new work. A refresh retains previously completed colors until new results arrive. Each pathological mesh receives at most two worker attempts per input revision and settles on a stable bounded fallback. Source-level changes cancel stale jobs. Hulls survive region-only refreshes. Large retired results/world ownership are reclaimed on the worker rather than as a result of a frame lookup. Turning the option/World/Viewer off or losing the companion cancels preparation; Vulkan instance destruction explicitly stops the worker.
