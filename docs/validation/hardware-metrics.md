# Hardware rows and the 6.66 LAB HUD: local preview 0.8.18

The 0.8.17 user log reported an unrecognized LAB telemetry executable for the installed base 6.66 build. The separate native layer already recognized it, but no managed session could start. This prevented the LAB Plus indicator and changed cheat-cvar/player-cheat HUD from connecting. The installed executable has MD5 `8e4462adcc44dc89287f687939a96af3`, PE timestamp `0x61692c83`, and image size `0x1e4cd000`.

Added an exact managed profile for that executable. The independently verified static integer locations are `com_showConsumerPerfMetrics` at RVA `0x43d3d70` and `com_adaptiveTickMaxHz` at `0x43d6130`; each is checked against its named registration constructor, using the same static-wrapper layout as existing profiles. Player and gameplay state use the already audited native game-system/map/player/HUD chain rather than importing legacy globals from a neighboring patch. The player vtable, deleted flag, game-system state, map identity, paused HUD and menu bounds are checked before exposing gameplay data. The legacy driver-string location is omitted on this new profile because driver hiding is implemented in the formatter and lighting correction is ineligible on 6.66.

The existing Hide AMD driver line setting now also suppresses the two original CPU/GPU name rows, independent of manufacturer, model, capitalization or percent signs. Their caller return addresses are resolved within the verified formatter block, between the Vulkan-version and VRAM calls. Exactly two calls to the same formatter are required. Other metrics calls are preserved; the original AMD driver-label filtering remains in place. Replaced formats are preserved. When DESRU has rewritten the frame-time format, its reused CPU/GPU argument buffers are also preserved, including trainer values and arbitrary scroll text. Original hardware rows remain available when hiding is disabled in coexistence mode; standalone metrics retain the established FPS/indicator-only behavior. Closing the companion or expiry of its lease restores original formatting.

The adapter format signature is now `LPMET004`; older retained adapters require a game restart. No game buffers containing CPU/GPU model strings are overwritten. The launch-only ownership guard from 0.8.17 is retained.

Validation passed: launcher regression checks; 333 managed/HUD checks including executed x64 formatter calls at separate synthetic hardware return addresses, toggle restoration, arbitrary hardware labels and original varargs; 399 checks when additionally resolving all 11 currently installed retail EXEs. Those retail checks cover exact managed profile recognition, both hardware call sites, cvar-registry metadata and player-cheat layouts. The native Vulkan DLL is unchanged from the tested 0.8.17 build. Positive gameplay/HUD acceptance remains to be performed after launching 6.66 through 0.8.18. No Wiki, game installations, saves or preferences were changed.

## 0.8.19: correction after the live DESRU reproduction

Read-only inspection of the user's running 6.66 process confirmed `LPMET004`, a live indicator lease, DESRU present and Hide enabled. DESRU had replaced the frame-time format while the original hardware labels were still being drawn. The 0.8.18 ownership heuristic consequently skipped every hardware row. Changed frame-time text is not evidence that DESRU owns the CPU/GPU argument buffers.

The filter no longer uses that heuristic. On the two verified hardware callers, when DESRU is present, it compares the argument against actual machine labels from the Windows processor description, Vulkan physical-device properties and Windows display-device descriptions. Manufacturer/model lists are not used. Both raw and trimmed labels are retained, with bounded UTF-8 records and ASCII case-insensitive matching. Arbitrary DESRU trainer/scroll text passes through; a real hardware label is suppressed even if DESRU changed the frame-time format. The immutable name bank fits inside the existing 4096-byte state region, and the new adapter signature is `LPMET005`.

The minimal-rights live diagnostic uses only VM_READ and QUERY_LIMITED_INFORMATION. Hardware enumeration succeeded on the current computer without changing game memory, input or installation files. A new executed x64 regression reproduces modified frame-time text together with a real hardware label and a differently cased name. Full launcher checks, 334 managed/HUD fixture checks and 400 checks with all 11 installed executable layouts passed. The retail game still has the old adapter until the user restarts it with 0.8.19; no visual acceptance is claimed for that running 0.8.18 process.
