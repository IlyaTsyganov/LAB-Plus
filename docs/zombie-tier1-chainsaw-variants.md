# Два передних распила Zombie Tier 1: выбор клипа

7 ноября 2026, retail 1.1. Уточнение к общему правилу выбора interactions v27.
Изменения production-кода и новая сборка в этой проверке не делались.

`syncdeath/playervsai/zombie_tier1/chainsaw/cut_front` содержит два варианта:
`cut_front_01` и `cut_front_02`. Это одна декларация с общими условиями aim/range.
Задний распил — отдельная декларация `.../chainsaw/cut_back`.

## Что проверено

В текущем процессе только чтением подтверждены:

* количество передних вариантов — 2;
* `chosenBy` — 1 (`SYNC_ANIM_CHOSEN_LEASTUSED` по native enum);
* declaration `debug_forceAnimIndex` — -1;
* глобальный force-index — -1.

Сохранённые назначенные декларации и четыре blueprint-вариации T1 используют
эту общую переднюю декларацию. Функция выбора конкретного клипа — RVA
`18d8570`, ветка LEASTUSED — `18d863f..18d86f9`.

Она сначала выбирает псевдослучайный начальный индекс. Если передан объект
статистики использования (второй аргумент), затем обходит варианты с этого
индекса и ищет наименьший счётчик (`18de670`, поле результата `+68`). При равных
счётчиках остаётся первый в этом случайно начатом обходе. Если статистика
не передана, возвращается сам случайный индекс (`18d8687..18d868a`, `18d86f6`).

Критическая деталь обычного запуска: функция исполнения `18d1a30` **повторно**
выбирает вариант и перед вызовом `18d8570` обнуляет второй аргумент:

```
18d1b2f xor edx, edx
18d1b36 mov rcx, r13    ; выбранная декларация
18d1b39 call 18d8570
```

Следовательно, для этого обычного пути при указанных force-index -1
передний клип выбирается псевдослучайно при запуске, несмотря на имя режима
LEASTUSED. Подготовленный ранее `interaction.animationInfo` не является
гарантией конкретного исполняемого варианта. Это вывод из кода исполняемого
файла и текущих настроек; аппаратная запись исполнения именно T1 в этой
проверке не проводилась.

Генератор в этой ветке обновляет общее состояние игры:
`s = (1664525*s + 1013904223) mod 2^32`, затем
`index = ((s >> 10) & 32767) % count`. Между предварительным чтением состояния
и нажатым распилом его могут потреблять другие игровые операции. Поэтому
по положению игрока, прицелу или прошлому распилу нельзя надёжно определить
01/02; строгого чередования код не обеспечивает. Во время запуска выбранный
вариант уже скопирован в `idSyncAttack.animationInfo` (`+2d8`).

## Следствие для визуализации

Выбор передней или задней **декларации** по-прежнему определяется приоритетом
и ближайшим подготовленным стартом. Внутри передней декларации правильно
показывать общую область с вариантами `cut_front_01 / cut_front_02`, помеченную
как случайный вариант клипа. Это не случайная полоса расстояния 0,381 м.
Подпись подготовленного клипа в v27 следует читать как снимок подготовки,
а не обещание исполнения именно этого переднего варианта.

Локальные материалы: `build/sync-animation-variant-body-v28.log`,
`build/sync-animation-variant-execution-v28.log`,
`build/sync-animation-variant-callers-v28.log`,
`build/variant-inspect-v28.py`. Суффикс v28 обозначает исследование,
а не выпущенную сборку.
